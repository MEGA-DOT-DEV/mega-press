# Experiments and promotion gates

This is an iteration record, not a claim that a framework rewrite is complete. Commands and browser receipts are collected in [verification.md](verification.md). Nothing here treats unavailable Figma art as inspected evidence.

## Iteration 0 / Identify the actual promises

The previous review found a substantial static renderer with 172 passing tests, not an empty foundation. Its strongest assets are the shared visual cabinet, precomputed geometry, named refusals, and existing consumer adoption.

The limiting questions are different:

- Does successful authoring preserve the source's meaning and bytes?
- Is a novel subject expressible without a one-off stylesheet?
- Is content readable at its delivered size, not just inside the artboard?
- Can an interaction be explained as a state transition with a stable target?
- Can both consumers advance without adopting a different engine?

## Iteration 1 / Put fidelity before more templates

`lab/framework/probe-legacy.mjs` makes three current gaps repeatable:

1. A code literal containing `2019–2024` compiles to `2019,2024`.
2. Bars discovery asks for `unit`; a catalogue-shaped plan with `days` compiles to `share`.
3. The existing overflow fixture passes `buildArtifact` but fails full geometric proof.

**Design change:** name the intermediate stages and make preservation non-negotiable. No unit/byte substitution is a layout accommodation. Keep the legacy output in the study instead of fixing it silently and losing the comparison.

## Iteration 2 / Smallest useful recipe experiment

The isolated lab uses a single `sequence` descriptor with strict fields, unique semantic IDs, versioned authored content, and a constrained item budget. The same recipe is exercised by a checked tool call, a simplified catchment-water route, and an integrity stress case. These are original illustrative fixtures, not claims extracted from a source article.

**What this can establish:** one semantic recipe can cross subject domains without changing its visual rules; schema validation can preserve valid input exactly; catalogue and shape constraints can share an authority.

**What it cannot establish:** arbitrary graphs, charts, nesting, mathematical notation, rich code blocks, asset layouts, or all future subjects fit this recipe. Do not conflate a subject-general sequence with a universal artifact language.

**Next falsifier:** exercise a second genuinely different semantic recipe through the existing composition path and a reconciled definition. Prefer a quantitative chart or access boundary. If the definition requires dozens of unrelated exceptions, redesign the boundary before migrating the catalogue.

## Iteration 3 / Delivered-size reading versus fixed-frame geometry

The live control calls the actual production parser/compiler/mount at a phone-width host. The reading study keeps body text at a proposed 16 CSS pixels and lets document height grow. Reading width is a host constraint. In the reference-aligned iteration, named ground/frame treatments are optional authored choices; neither surface exposes coordinates.

This study does **not** solve responsive geometry through the production solver. Its CSS/browser layout must be measured, and any promoted layout needs a formal preparation path and publication gate.

**Checks:**

- 390px and 360px viewport; no document-level horizontal overflow.
- Same title and all four step details present verbatim in reading DOM.
- No hidden or clipped essential content in wide/narrow variants.
- Keyboard can reach every action; selected state is not communicated by colour alone.
- Mobile size does not force the new reading body below its floor.
- The legacy control's 340px minimum stays locally scrollable where needed; do not mask it as a new-engine success.

**Next falsifier:** compare bounded recipes under dense technical labels and relational topologies, not only short linear text. If meaning is lost when reflowing, refuse the profile or provide an explicit alternate reading view rather than inventing a new topology.

## Iteration 4 / Grounds that do not compete with content

The initial quiet, lattice, and flow studies were original token-based proposals. Iteration 6 supersedes the latter two with inspected design references and existing field code. Background geometry is decorative and ignored by assistive technology. Text sits on opaque quiet surfaces, not unmeasured image luminance.

**Review questions:** does a field add hierarchy or just noise? Does a lattice imply a quantitative axis? Are textures still useful at 390px? Can the same cabinet frame a nontechnical subject without relying on code-like decoration?

**Next input:** authorized screenshots or SVGs of the actual visual references. Extract composition rules, not arbitrary one-off coordinates. No design decision here is justified by the five export-disabled-dialog JPEGs.

## Iteration 5 / State is independent of playback

The experimental controller supports focus/select, clear, and next-step actions. The browser logs semantic envelopes locally. An emphasis sampler can be driven by explicit progress or a disposable browser clock. Seeking the presentation is not recorded as user interaction with the artifact.

**Checks:** deterministic state/event order; stable target and instance identity; no-op/invalid suppression; unsubscribe/dispose; no event text leakage; observer failure isolation; reduced motion; cancellation on fixture changes; repeated time samples produce the same pose.

**What remains unproved:** general transition geometry, serialized state restoration, source-version changes, image/font settlement across environments, export frame reproducibility, and real host integration.

**Next falsifier:** mount one specimen simultaneously in two host adapters, restore each state, interrupt a transition, dispose/remount, and verify zero cross-instance leakage. This is a gate before promoting the old interaction prototype or introducing persistent analytics.

## Iteration 6 / Reference-aligned, fewer parts

Inspected Mega-Dev's token contract, field/static pages, and relevant local implementations. Inspected five stored Mega-Content specimens and representative composition/motion source, supported by a read-only research agent. [Design alignment](design-alignment.md) records source provenance and limits.

**Design change:** much of the needed expression already exists. Prefer exposing named compositions/attachments and adding a small semantic callback at the existing transition point over introducing another registry, scene DSL, or runtime. The earlier package-entry diagram is a possible environment boundary, not a plan to split the package.

**Lab change:** removed the drawn flow SVG and dot lattice. Added optional schema-owned background/frame-treatment choices, reused Press's Bayer field/clearing, and raised short-label microcopy to 12px. Authoring choices create a new revision and no reader-interaction event. No new shader, animation loop, external asset, public export, or consumer dependency.

**Next falsifier:** can the existing composition and interaction functions meet the new trust/readability/event contract with fewer changes than a replacement? If yes, discard the redundant lab mechanism. Prototype machinery does not earn production status by already being written.

## Iteration 7 / Actual compositions, insufficient expressiveness evidence

The seven-frame gallery re-renders four familiar compositions and three new combinations through canonical `evaluateSpec → mount`. It covers landscape, square and portrait, host title visibility, component attachments, simple branching, intervals and a selectable sequence. Its 18 additional tests bring the lab total to 35. It is not a new public authoring schema; the two sparse square frames retain their warnings.

**Author verdict:** these examples are too simple for the actual technical-content need. A passing gallery must not be reported as approval of the framework's expressive range.

## Iteration 8 / Dense technical reference corpus

Directly inspected all nine new PNGs: schema comparison, scheduler, execution trace, provider architecture, grouped behavior layers, scope/table/comparison, compound architecture with sidebar, annotated transcription waveforms and trigger flows. The author also explicitly requires screenshots, quantitative charts, statistics with timelines, transformations, annotated prose and architecture legends.

**Design change:** ordinary author/model composition must support nested structured node bodies, semantic relations, shared categories/legends/annotations and measured media/SVG. Templates are optional conveniences, not an implementation boundary. Fixed 4:5 frames and blanket small item budgets cannot be the ceiling for long technical explanations. Reuse existing machinery where its actual contract fits; do not assume it already covers these cases.

The [technical study](technical-composition.md) records all references, the revised responsibilities, asset safety and interaction requirements, and three hard proving examples. Those examples are not implemented yet. Their failure criteria supersede the earlier suggestion that one more simple chart/boundary would be enough to challenge the abstraction.

## Next comparison / Challenge the abstraction

First test the supplied dense corpus without simplifying away the difficult structures. Then broaden beyond the synthetic sequence fixtures to twelve **real, author-reviewed** artifacts: four technical explanations, four nontechnical/editorial pieces, and four evidence/data presentations. These are a proposed corpus, not twelve completed specimens. Include at least a branching relationship, a quantitative comparison with units, dense labels, and a narrative that should not be forced into a process diagram.

Author each through A and B. Record semantic edits requested, schema-discovery effort, new primitives, composition exceptions, and author preference. Reconsider B if it repeatedly relocates complexity rather than reducing it; an initial discussion threshold is more than two artifacts needing unique new primitives. Agree that threshold with the author rather than treating it as a universal metric.

Test reading, square, portrait, and a required wide frame separately. Preserve content and reading order across every supported profile. Repeated semantic rewrites challenge B's reuse premise; recurring cross-cutting spatial constraints strengthen the case for C. Finally, replay a branching explanation at exact sample times: a hidden general scene graph reconstructed inside an adapter is evidence to revisit the boundary.

The reference register now includes Mega-Dev and Mega-Content, as described in Iteration 6. Extend it with real authored content rather than manufacturing a twelve-item success corpus. Consumer source stays read-only during this research.

## Evidence before promotion

| Area | Required production evidence |
| --- | --- |
| Authoring | Every advertised example passes its own schema, lowering, semantic preservation, and preparation gate; every refused example names an actionable path |
| Meaning | Values, labels, units, IDs, code bytes, and graph relationships survive round-trip and profile changes |
| Geometry | Golden solved layouts and browser screenshots at actual delivery sizes; no hidden truncation; supported glyph/font coverage is explicit |
| Accessibility | Reading order, headings, chart data/relationships, keyboard control, focus indication, reduced motion, forced colours, and zoom/manual assistive-tech review |
| Runtime | State/action determinism, event schema and source, instance identity, observer isolation, teardown, and validated restoration |
| Motion | Identical samples for identical inputs/time, valid intermediate states, explicit interruption policy, asset-complete capture |
| Delivery | Old stored content works; separate producer/consumer pins; server-safe imports; no lab import; reviewed rollback path |

Unit tests are necessary but cannot certify taste, teaching value, factual truth, or usability. Keep author review and real content in the loop.
